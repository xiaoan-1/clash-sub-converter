下面两种方式二选一，地址是同一个，区别只在客户端把它填到哪个输入框。
方式一：直接当「订阅地址」推荐
先保存上面的订阅地址，再把下面这条填进客户端的「订阅地址」。 之后自动更新由本服务完成，不需要再打开网页。
/sub
方式二：OpenClash「在线订阅转换」
本方式是让 OpenClash 把机场订阅交给我们转换。要填四个地方，缺一不可：
  1. 勾选「在线订阅转换」 —— 不勾就不会拼接参数，OpenClash 会把服务地址当普通订阅直接下载
  2. 订阅转换服务地址 —— 填下面这条，只填到 /sub， 不要自己加 ?target=... 之类参数
  3. 订阅地址 —— 填机场给你的原始订阅链接（ OpenClash 会自动追加成 ?url=...）
  4. 订阅转换模板 —— 必须选一个具体的模板（选哪个都行）。 本服务自带完整分组与分流规则，会忽略模板内容； 但这个字段不能空着，否则转换根本不会发生：
    ⚠️ 选了「自定义模板」却把地址留空 = 完全不会转换。
    OpenClash 的逻辑是「模板为空 → 直接下载机场原始订阅」， 连转换服务都不会请求，你看到的仍是机场原配置（分组是机场自己的名字）。
    解决：改选任意一个内置模板；或选「自定义模板」并填任意一个非空地址（内容会被忽略）。
/sub
⚠️ OpenClash 里这个字段默认填的是 api.asailor.org， 那是第三方公共服务 —— 订阅地址会连同 token 一起发给它。 请务必改成下面这条你自己的地址。
⚠️ 方式一按「请求来源 IP」区分订阅：保存与拉取必须来自同一出口 IP。 路由器上的 OpenClash 与电脑不是同一个 IP，因此路由器场景请用方式二。 部署在 Nginx / Caddy 后面时需设置 TRUST_PROXY。

订阅拉取设置

转换器代拉订阅时发送的客户端标识（User-Agent）。若与实际客户端不一致， 机场可能判定为「非本人操作 / 订阅地址泄漏」而作废订阅地址。
选「跟随调用方」时，仅当请求确实来自代理客户端（Clash / OpenClash / sing-box 等） 才原样透传其 UA；浏览器 / curl 等非客户端请求会回退到 Clash Verge， 避免把通用 UA 转给机场而暴露「这不是客户端在拉取」。
