# 数据流通路径

本文档说明 OpenClash 请求从接收到返回完整 Clash YAML 的完整数据流，涵盖所有文件和关键函数。

---

## 一、请求流程概览

```
OpenClash 客户端
    │
    │  GET /sub?target=clash&url=...&include=...&exclude=...&udp=true
    ▼
┌──────────────────────────────────────────────────────────────┐
│  index.js (HTTP 入口)                                        │
│                                                              │
│  1. 解析请求参数                                              │
│  2. fetchSubscription(url)                                   │
│     └→ HTTP GET 订阅源 → 原始文本                             │
│  3. parseSubscription(content)                               │
│     └→ src/parser.js → proxies[] (统一代理对象数组)           │
│  4. parseRuleOptions(include, exclude)                       │
│     └→ 解析 OpenClash 规则过滤参数                            │
│  5. convertToClash(proxies, { ruleOptions })                 │
│     └→ src/converter.js → 完整 Clash YAML                    │
└──────────────────────────────────────────────────────────────┘
    │
    │  HTTP Response: text/yaml
    ▼
OpenClash 客户端收到配置
```

## 三、各阶段详细说明

### 阶段一：HTTP 请求接收

**文件**：`index.js`，路由 `GET /sub`

```js
app.get('/sub', async (req, res) => {
  const { target, url, include, exclude, emoji, udp, scv, sort, append_type } = req.query;
  const urls = url.split('|').map(u => u.trim()).filter(Boolean);
  // ...
});
```

**关键点**：
- 多个订阅源用 `|` 分隔
- `target` 决定输出格式（`clash` 或 `surge`）

### 阶段二：获取订阅内容

**文件**：`index.js`，函数 `fetchSubscription(url)`

```js
async function fetchSubscription(url) {
  const response = await fetch(url, {
    headers: { 'User-Agent': 'ClashForAndroid/2.5.12', 'Accept': '*/*' },
    signal: AbortSignal.timeout(15000)
  });
  return await response.text();
}
```

- 15 秒超时
- 返回原始文本（Base64 或明文协议列表）

### 阶段三：协议解析

**文件**：`src/parser.js`，入口 `parseSubscription(content)`

```
原始文本
  ├─ isBase64() → base64Decode() → 逐行拆分
  └─ 明文 → 逐行拆分
      │
      ▼
  每行识别协议前缀 → 对应解析器 → proxy 对象
```

各解析器输出统一结构，详见 `docs/协议解析输出.md`。

**兼容性映射**：
- SSR → `type: 'ss'`（Clash 不支持 SSR）
- VLESS → `type: 'vmess'`（Clash 不支持 VLESS）

### 阶段四：规则选项解析

**文件**：`index.js`，函数 `parseRuleOptions(include, exclude)`

```
include=(?i)telegram|openai
    │
    ├─ 拆分为 ['telegram', 'openai']
    ├─ patternMatchGroup() 与 RULE_GROUP_ALIASES 匹配
    │   telegram → ['telegram', 'tg']
    │   openai   → ['openai', 'chatgpt', 'gpt']
    ▼
ruleOptions = {
  includeTelegram: true,
  includeOpenai: true,
  includeYoutube: false,   // 未匹配
  includeNetflix: false,
  ...
}
```

**支持的 10 个规则组别名**：

| 规则组 | 别名 |
|--------|------|
| telegram | telegram, tg |
| openai | openai, chatgpt, gpt |
| youtube | youtube, ytb |
| netflix | netflix, nf |
| disney | disney, disneyplus |
| dazn | dazn |
| bahamut | bahamut |
| bilibili | bilibili, bili |
| github | github, gh |
| mihoyo | mihoyo, hoyoverse |

### 阶段五：配置组装

**文件**：`src/converter.js`，函数 `convertToClash(proxies, options)`

组装 5 个部分：

```js
const config = {
  'mixed-port': 7890,           // 基础配置
  'allow-lan': true,
  mode: 'rule',
  dns: getDefaultDNS(),          // fake-ip DNS
  proxies: proxies,              // ← parser.js 输出
  'proxy-groups': generateProxyGroups(proxies),  // ← proxy-groups.js
  rules: generateRules(ruleOptions)              // ← rules/rules.js
};
```

#### 子模块 1：代理分组生成

**文件**：`src/proxy-groups.js`

```
proxies[] → getRegion(nodeName) → 匹配 22 个地区关键词
    │
    └→ 自动生成 20+ 分组：
       ├─ 🚀节点选择 (select)
       ├─ ♻️自动选择 (url-test)
       ├─ 地区分组：🇭🇰香港/🇯🇵日本/🇺🇸美国/🇸🇬新加坡/...
       ├─ 服务分组：📲Telegram/🤖OpenAI/▶️YouTube/🎬Netflix/...
       └─ 🐟漏网之鱼 (兜底)
```

#### 子模块 2：规则生成

**文件**：`src/rules/rules.js`

```
ruleOptions → 按 include/exclude 过滤
    │
    └→ 生成 10 组规则：
       ├─ Telegram: DOMAIN-SUFFIX,telegram.org → 📲 Telegram
       ├─ OpenAI:   DOMAIN-SUFFIX,openai.com → 🤖 OpenAI
       ├─ YouTube:  DOMAIN-SUFFIX,youtube.com → ▶️ YouTube
       ├─ Netflix:  DOMAIN-SUFFIX,netflix.com → 🎬 Netflix
       ├─ ...
       └─ MATCH,🐟 漏网之鱼 (兜底)
```

### 阶段六：YAML 序列化 + HTTP 响应

**文件**：`src/converter.js` + `index.js`

```js
// converter.js
return yaml.dump(config, {
  lineWidth: -1,
  noRefs: true,
  sortKeys: false,
  quotingType: "'",
  forceQuotes: false
});

// index.js
res.type('text/yaml').send(result);
```

## 四、请求示例

```
GET /sub?target=clash
        &url=https://example.com/sub.txt
        &include=(?i)telegram|openai
        &exclude=(?i)广告
        &udp=true
```

| 参数 | 值 | 作用 |
|------|----|------|
| `target` | `clash` | 输出格式，调用 `convertToClash` |
| `url` | `https://example.com/sub.txt` | 订阅源地址 |
| `include` | `(?i)telegram\|openai` | 只启用 telegram 和 openai 规则组 |
| `exclude` | `(?i)广告` | 排除广告相关规则 |
| `udp` | `true` | 启用 UDP |

最终返回：仅包含 Telegram + OpenAI 规则的完整 Clash 配置。

## 五、函数调用链

```
GET /sub
  └→ fetchSubscription(url)                    # index.js
  └→ parseSubscription(content)                # src/parser.js
  │    └→ parseVmess / parseSS / parseSSR / ...  # src/parser.js
  └→ parseRuleOptions(include, exclude)        # index.js
  │    └→ patternMatchGroup(pattern, groupKey) # index.js
  └→ convertToClash(proxies, options)          # src/converter.js
       ├→ generateProxyGroups(proxies)         # src/proxy-groups.js
       │    └→ getRegion(name)                 # src/proxy-groups.js
       ├→ generateRules(ruleOptions)           # src/rules/rules.js
       └→ yaml.dump(config)                    # js-yaml
```

## 六、文件职责总览

| 文件 | 职责 | 输入 | 输出 |
|------|------|------|------|
| `index.js` | HTTP 入口 + 请求处理 | HTTP 请求参数 | YAML 响应 |
| `src/parser.js` | 6 种协议解析 | 原始文本 | `proxies[]` |
| `src/converter.js` | 配置组装 + YAML 序列化 | `proxies[]` + `ruleOptions` | YAML 字符串 |
| `src/proxy-groups.js` | 代理分组（按地区/服务） | `proxies[]` | `proxyGroups[]` |
| `src/rules/rules.js` | 路由规则（10 组服务） | `ruleOptions` | `rules[]` |
| `src/utils.js` | 工具函数 | — | Base64/UUID/URL 解析 |

**项目结构**：
```
clash-sub-converter/
├── index.js                ← HTTP 入口 + 路由 + 规则选项解析
├── src/
│   ├── parser.js           ← 解析层：6 种协议 → proxies[]
│   ├── converter.js        ← 组装层：合并所有部分 → YAML
│   ├── proxy-groups.js     ← 分组：按地区/服务自动归类
│   ├── rules/
│   │   └── rules.js        ← 规则：10 组服务路由规则
│   └── utils.js            ← 工具函数
└── docs/
    ├── 格式说明.md          ← 输入输出格式规范
    ├── 协议解析输出.md      ← 各协议解析结果结构
    └── 数据流通路径.md      ← 本文档
```
