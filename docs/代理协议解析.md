# 协议解析输出说明

本文档说明各协议解析后的统一输出结构。

解析器已按分类拆分到 `src/parser/` 目录：入口 `src/parser.js` 负责格式识别与协议调度，各协议实现在 `src/parser/<协议>.js`（见下表）。新增协议只需在入口的 `PROTOCOL_PARSERS` 注册表登记一行。

所有协议解析后都会输出为统一的 proxy 对象，最终写入 Clash 配置的 `proxies` 字段。

> **额外兼容**：`parseSubscription()` 还会自动识别 Clash YAML 格式输入（含 `proxies:` 数组），直接提取其中的节点，无需协议转换。

## 1. VMess

**输入格式**：`vmess://Base64(JSON)`

```js
{
  name: '节点名称',            // 来自 JSON.ps，缺省则为 server:port
  type: 'vmess',
  server: 'server.example.com', // 来自 JSON.add
  port: 443,                    // 来自 JSON.port
  uuid: 'xxxxxxxx-xxxx-...',    // 来自 JSON.id
  alterId: 0,                   // 来自 JSON.aid，默认 0
  cipher: 'auto',               // 固定值
  udp: true,
  // ---- 以下字段按需出现 ----
  network: 'ws',                // JSON.net: tcp(默认) / ws / h2 / grpc / http
  'ws-opts': {
    path: '/',
    headers: { Host: '...' }
  },
  'h2-opts': {
    host: ['...'],
    path: '/'
  },
  'grpc-opts': {
    'grpc-service-name': '...'
  },
  'http-opts': {
    path: ['/'],
    method: 'POST',
    headers: { Connection: ['keep-alive'], Host: ['...'] }
  },
  tls: true,                    // JSON.tls === 'tls'
  sni: '...',                   // JSON.sni
  alpn: ['h2', 'http/1.1'],    // JSON.alpn（逗号分隔拆为数组）
  'skip-cert-verify': true      // JSON.allowInsecure === '1'
}
```

## 2. Shadowsocks (SS)

**输入格式**：
- SIP002：`ss://Base64(method:password)@server:port#name`
- 旧格式：`ss://Base64(method:password@server:port)#name`

```js
{
  name: '节点名称',            // # 后解码，缺省则为 server:port
  type: 'ss',
  server: 'server.example.com',
  port: 8388,
  password: 'mypassword',
  cipher: 'aes-256-gcm',       // 加密方式，缺省为 aes-256-gcm
  udp: true
}
```

---

## 3. ShadowsocksR (SSR)

**输入格式**：`ssr://Base64(server:port:protocol:method:obfs:Base64(password)/?params)`

```js
{
  name: '节点名称',            // 来自 remarks 参数，缺省则为 server:port
  type: 'ss',                  // ⚠️ 降级为 ss 类型
  server: 'server.example.com',
  port: 8388,
  password: 'mypassword',
  cipher: 'aes-256-cfb',       // 来自 SSR 的 method 字段
  udp: true
}
```

> ⚠️ Clash 不原生支持 SSR，解析时丢弃 `protocol`、`obfs` 等字段，降级为 SS 使用。

## 4. Trojan

**输入格式**：`trojan://password@server:port?params#name`

```js
{
  name: '节点名称',            // # 后解码，缺省则为 server:port
  type: 'trojan',
  server: 'server.example.com',
  port: 443,
  password: 'mypassword',      // 来自 URL.username
  udp: true,
  // ---- 以下字段按需出现 ----
  sni: '...',                  // sni 或 peer 参数
  'skip-cert-verify': true,    // allowInsecure=1
  network: 'ws',               // type=ws
  'ws-opts': {
    path: '/',
    headers: { Host: '...' }
  },
  'grpc-opts': {               // type=grpc
    'grpc-service-name': '...'
  }
}
```

## 5. VLESS

**输入格式**：`vless://uuid@server:port?params#name`

```js
{
  name: '节点名称',            // # 后解码，缺省则为 server:port
  type: 'vmess',               // ⚠️ 映射为 vmess 类型
  server: 'server.example.com',
  port: 443,
  uuid: 'xxxxxxxx-xxxx-...',   // 来自 URL.username
  alterId: 0,                  // 固定 0
  cipher: 'auto',              // 固定值
  udp: true,
  // ---- 以下字段按需出现 ----
  tls: true,                   // security=tls
  sni: '...',                  // sni 参数
  network: 'ws',               // type 参数: ws / grpc
  'ws-opts': {
    path: '/',
    headers: { Host: '...' }
  },
  'grpc-opts': {
    'grpc-service-name': '...'
  }
}
```

> ⚠️ Clash 原生不支持 VLESS，解析时映射为 `vmess` 类型（alterId=0, cipher=auto）。

## 8. TUIC

**输入格式**：`tuic://uuid:password@server:port?params#name`（V5）或 `tuic://token@server:port?params#name`（V4）

> Clash YAML 输入的 `type: tuic` 节点直接透传；此处为 URI 链接的解析结构。

```js
{
  name: '节点名称',            // # 后解码，缺省则为 server:port
  type: 'tuic',
  server: 'server.example.com',
  port: 443,
  udp: true,
  // ---- 以下字段按需出现 ----
  uuid: '...',                // userinfo 含冒号时取前段（V5）
  password: '...',            // userinfo 含冒号时取后段（V5）
  token: '...',               // userinfo 无冒号时整体作为 token（V4）
  sni: '...',                 // sni 参数
  alpn: ['h3'],               // alpn 参数（逗号分隔拆为数组）
  'congestion-controller': 'bbr',   // congestion_control / congestion-controller 参数
  'udp-relay-mode': 'native',       // udp_relay_mode / udp-relay-mode 参数
  'skip-cert-verify': true    // allowInsecure/insecure=1
}
```

## 9. Hysteria（v1）

**输入格式**：`hysteria://auth@server:port?params#name`

```js
{
  name: '节点名称',
  type: 'hysteria',
  server: 'server.example.com',
  port: 443,
  up: '20 Mbps',               // up 参数，缺省 '20 Mbps'
  down: '50 Mbps',             // down 参数，缺省 '50 Mbps'
  udp: true,
  // ---- 认证（三选一）----
  'auth-str': '...',           // auth-str 参数或 userinfo
  auth: '...',                 // auth 参数（base64 用户名:密码）
  // ---- 以下字段按需出现 ----
  obfs: '...',                 // obfs 混淆类型
  protocol: 'udp',             // udp / wechat-video / faketcp
  alpn: ['h3'],                // alpn 参数
  sni: '...',
  'skip-cert-verify': true
}
```

  'pre-shared-key': '...',     // psk/pre-shared-key 参数

- **SSR → `ss`**：Clash 不支持 SSR 协议，降级为 SS
- **VLESS**：直接输出 `vless` 类型（mihomo 原生支持）
- **Snell / SOCKS5 / HTTP / WireGuard**：Surge 输出时按对应类型转换；其余（Hy1/ShadowQUIC 等）Surge 不支持则跳过
