# 日志与排查

本项目自带一套把**整条订阅转换链路**（拉取 → 解析 → 过滤 → 分组 → 规则 → 输出）
落盘的日志，用于排查「节点少了 / 转换报错 / 客户端订阅详情空白」这类问题。

## 日志文件

| 文件 | 内容 | 说明 |
|---|---|---|
| `logs/app.log` | 全部级别（含 `DEBUG`），完整流程轨迹 | 排查首选项，默认级别 `debug` |
| `logs/error.log` | `WARN` + `ERROR` | 只想看问题时看这个 |
| `logs/app.log.1` / `logs/error.log.1` | 上一份日志 | 单个文件超过 5MB 时自动轮转，只保留一份历史 |
| `logs/pm2-out.log` / `logs/pm2-error.log` | PM2 自己捕获的 stdout / stderr | 由 PM2 写入，与应用自身日志分开，避免两个写入方交错破坏日志行 |

`logs/` 已在 `.gitignore` 中忽略，不会进版本库。

## 日志格式

```
2026-10-06 12:34:56.789 INFO  [sub#3f9a1c] 拉取订阅成功 url=https://api.example.com/api/v1/client/subscribe ua=clash-verge/v1.7.7 dur=842ms status=200 content-type=text/yaml; charset=utf-8 bytes=126.5KB
```

拉取失败时是这两行（详见「场景 0」）：

```
2026-10-06 12:35:02.101 WARN  [fetch] 拉取订阅失败：服务端返回错误状态码 url=https://api.example.com/api/v1/client/subscribe host=api.example.com ua=OpenClash/v0.46.0 ua-source=config:openclash（预设） dur=21ms fail-stage=http status=403 status-text=Forbidden server=openresty cf-ray=8a1b2c3d-HKG www-authenticate=Bearer realm="airport" content-type=application/json; charset=utf-8 body-bytes=152B response-body={"message":"订阅已过期，请续费后重新获取","token":"***"} reason=HTTP 403 Forbidden hint=禁止访问：订阅地址已失效，或拉取所用 UA 被机场安全规则拦截
2026-10-06 12:36:01.777 WARN  [fetch] 拉取订阅失败：请求未能完成 url=https://api.example.com/api/v1/client/subscribe host=api.example.com ua=OpenClash/v0.46.0 ua-source=config:openclash（预设） dur=15.01s fail-stage=timeout reason=超时（15.00s 内未拿到响应） net-hint=对端在超时时间内未响应：机场侧慢或被网络阻断 hint=只有这一个订阅超时 → 多半是机场侧问题；所有订阅都超时 → 检查本机网络 / DNS / 代理。
```

- `2026-10-06 12:34:56.789` —— 自带毫秒时间戳。此前日志的时间戳来自 PM2 的 `log_date_format`，
  直接 `node index.js` 跑时没有时间戳，无法对齐事件先后。
- `INFO` —— 级别，`DEBUG` / `INFO` / `WARN` / `ERROR`
- `[sub#3f9a1c]` —— scope。`#` 后面是**请求编号**，同一请求的所有日志行共用它，
  多客户端并发时按这个编号 `grep` 就能把一条完整链路挑出来。
- 其余为 `键=值` 字段，值为数组时形如 `[a, b, c]`(3)，末尾括号是总长度。

各级别的 scope（也就是 `grep` 用什么）一览：

| scope | 模块 | 关键内容 |
|---|---|---|
| `app` | `index.js` 启动 | 端口、PID、Node 版本、日志文件位置 |
| `sub#xxxxxx` | `index.js` `/sub` | 入口参数、每份订阅拉取结果、解析结果、转发的订阅信息头、耗时与状态码 |
| `api/convert#xxxxxx` | `server/api.js` `/api/convert` | 同上，走 JSON 接口的那条路径 |
| `api` | `server/api.js` 其他端点 | `/api/parse`、`/api/convert-file`、`/api/config` |
| `fetch` | `src/utils.js` | 单次 HTTP 拉取：URL（已脱敏）、UA **与 UA 来源**、失败阶段、状态行、关键响应头、响应正文摘要、网络错误码 |
| `parser` | `src/parser.js` | 每份订阅的格式判定、节点数、类型分布、被丢弃的行 |
| `converter` | `src/converter.js` | 过滤前后节点数、命中的排除关键词、分组数、规则数、YAML 大小 |
| `groups` | `src/proxy-groups.js` | 国内/国际节点分类、每个分组的成员数、被移除的悬空引用 |
| `rules` | `src/rule-manager.js` | 规则文件加载结果、启用的规则分组、生成规则条数 |
| `config` | `src/user/user-config.js` | 用户配置的读取与保存 |

## 级别控制

通过环境变量调整，不必改代码：

| 变量 | 默认 | 作用 |
|---|---|---|
| `LOG_LEVEL` | `debug` | 写入 `logs/` 文件的最低级别 |
| `LOG_CONSOLE_LEVEL` | `info` | 输出到控制台的最低级别 |
| `LOG_MAX_BYTES` | `5242880` | 单文件体积上限（字节），超出后轮转 |

PM2 部署时已在 `ecosystem.config.js` 的 `env` 中设置好这两个变量。

- 平时想安静一点：把 `LOG_LEVEL` 改成 `info`。
- 排查疑难问题：保持 `debug`，直接 `node index.js`（不走 PM2）也能看到 `INFO` 及以上的实时输出。

## 脱敏约定

订阅地址普遍把 token 直接写在路径或查询串里，**日志中不允许出现凭据**。
所有 URL 都经 `logger.safeUrl()` 处理：

```
原始：https://user:pass@api.example.com/api/v1/client/subscribe?token=AbCd1234...
写入：https://api.example.com/api/v1/client/subscribe?token=***
```

- `//user:pass@` 一段整体抹掉
- `token` / `sub` / `code` / `key` / `auth` / `pwd` / `password` / `sign` / `secret` / `access_key`
  这类查询参数的值替换为 `***`
- 路径里长度 ≥24 的字母数字串（订阅路径本身常就是凭据）替换为 `/***`

**节点内容一律不落盘**：解析失败的节点只记录 scheme + 错误原因
（旧实现在 `src/parser.js` 里打印 URI 前 50 字符，会把密码 / UUID 写进日志，已修掉）。

**响应正文摘要同样过脱敏**（`response-body`）：机场的错误正文里常带回 `token`，
`"token":"xxx"` 与 `token=xxx` 两种写法都会被抹成 `***`。

## 常见排查场景

### 0. 订阅拉取失败（最常见的报错，先看这个）

```powershell
Select-String -Path logs\app.log -Pattern '发起订阅请求|拉取订阅失败|拉取阶段结束|全部订阅拉取失败|无法获取任何订阅内容'
```

**第一步：看 `fail-stage`，它决定往哪个方向查。**

| `fail-stage` | 含义 | 相关字段 | 怎么读 |
|---|---|---|---|
| `http` | 连上了，服务端返回了错误状态码 | `status` `status-text` `response-body` `server` `cf-ray` `www-authenticate` `retry-after` | 机场往往把原因写在 `response-body` 里（订阅过期 / token 失效 / 限流） |
| `timeout` | 15 秒内没拿到响应 | `dur` `net-hint` `hint` | 只有这一个订阅超时 → 多半机场侧；全部超时 → 查本机网络 / DNS / 代理 |
| `connect` | 连接阶段就失败，**还没到机场的鉴权环节** | `net-code` `net-cause` `net-detail` `net-hint` | `ENOTFOUND`=域名写错、`ECONNREFUSED`=端口不对/被拦、证书类=链路上有 MITM 代理 |

**第二步：看「用了什么去订阅」。** 每次请求前都有一行：

```
[fetch] 发起订阅请求 method=GET url=… host=… ua=OpenClash/v0.46.0 ua-source=config:openclash（预设） accept=*/* timeout=15.00s redirect=follow
```

`ua-source` 直接说明这个 UA 是谁定的：

| `ua-source` | 含义 |
|---|---|
| `config:openclash（预设）` | 配置界面选的预设，正常情况 |
| `config:custom（配置页面手填）` | 配置里手填的 UA |
| `config:custom 但未填写，已回退 xxx` | 选了「自定义」却没填，实际用的是默认预设 |
| `config:auto（透传调用方）` | 调用方本身是代理客户端，把它的 UA 原样转给了机场 |
| `config:auto（调用方「Mozilla/5.0 …」不是代理客户端，回退 xxx）` | 浏览器 / curl / 脚本在拉，UA 不是客户端 |
| `?ua= 显式指定` | 订阅地址上带了 `&ua=` |

> **同一个订阅地址，客户端能拉、`/sub` 拉不到**，就先对比这行的 `ua` 与客户端的 UA。
> 403 / 406 / 451 多数是机场按 UA 判定「不是本人客户端」而拒绝；
> 去「配置界面 → 订阅拉取设置」选成与客户端一致的 UA 即可。

**第三步：看汇总行。** 全部订阅都失败时会汇总成一条：

```
[sub#040427] 全部订阅拉取失败，终止转换 total=6 by-stage={"http":4,"connect":2} by-reason={"HTTP 403 Forbidden":1,…} by-net-code={"ECONNREFUSED":1,"ENOTFOUND":1} ua-used=OpenClash/v0.46.0 ua-source=config:openclash（预设） failures=[https://… → HTTP 403 Forbidden, …](6) hint=…
```

- `by-stage` / `by-reason` / `by-net-code` —— 失败分类计数，一眼看出是同一类问题还是各不相同
- `failures=[地址 → 原因]` —— 每份订阅各一条（地址已脱敏），`code` 表示网络错误码
- `hint` —— 下一步该做什么

`/api/convert` 同样会打一条 `无法获取任何订阅内容，终止转换`，字段含义一致。

### 1. 客户端订阅详情（流量 / 到期）空白

```powershell
Select-String -Path logs\app.log -Pattern '订阅元信息|已转发订阅信息|订阅源未下发'
```

- 有 `订阅元信息 userinfo=upload=…` + `已转发订阅信息` → 服务端正常，问题在客户端是否读取响应头
- `订阅元信息 userinfo=(无)` → 该机场订阅源压根没下发 `subscription-userinfo`，与本服务无关
- 完全没有 `订阅元信息` 行 → 订阅没拉成功，往上找 `拉取订阅失败`

### 2. 节点数量比订阅里少

```powershell
Select-String -Path logs\app.log -Pattern '解析完成|节点过滤|关键词过滤移除|未识别|未被采用'
```

按顺序看这几行，每一步的输入/输出数量都写明了，能直接定位是哪一步吃掉了节点：

1. `源 1/2 解析完成 format=clash-yaml nodes=200` —— 解析阶段
2. `部分行未识别，已跳过 detail={...}` —— 不认识的 scheme（旧实现静默丢弃）
3. `Clash YAML 中有节点未被采用 declared=200 kept=180` —— 类型不受支持
4. `关键词过滤移除了节点 removed=20 hitKeywords=[...]` —— 命中了哪些排除关键词
5. `节点过滤 in=200 out=180` —— 国内/国际开关的影响

### 3. 转换报错

```powershell
Get-Content logs\error.log -Tail 50
```

`ERROR` 行附带截断的调用栈；`WARN` 行给出可操作的原因
（如「全部节点被过滤条件排除」会列出真正起作用的过滤条件）。

### 4. 某次请求的完整链路

从入口日志里拿到请求编号，例如 `[sub#3f9a1c]`：

```powershell
Select-String -Path logs\app.log -Pattern 'sub#3f9a1c'
```

### 5. 分组 / 规则数量不对

```powershell
Select-String -Path logs\app.log -Pattern '分组生成完成|分流规则加载完成|规则生成|规则分组被用户关闭'
```

- `规则分组被用户关闭，跳过` —— 说明该分组被配置关掉了（`config.json` 的 `groupOverrides`）
- `分流规则加载完成 loaded=18` —— 规则文件是否都读到了
- `分组中包含不存在的引用，已移除` —— mihomo 会因 `proxy not found` 拒绝整份配置，这里能看出被修掉的是哪一条

## 代码约定

新增日志时：

1. 用 `const log = logger.create('模块名')`，不要在业务代码里直接 `console.log`；
   请求级日志再拼上 `logger.reqId()`。
2. **URL 一律走 `logger.safeUrl()`**；不要记录请求/响应头对象、订阅正文、节点 URI。
3. 循环里的失败（解析失败、拉取失败）要**汇总后打一次**，不要每行一条。
4. 用 `logger.timer()` 记录耗时，用 `logger.formatBytes()` 记录字节数。
5. catch 块用 `log.fail('说明', err, { 附加上下文 })`，它会自动带上截断的调用栈。
6. `requestSubscription()` 抛出的异常上已挂好诊断字段：`status` / `statusText` / `responseBody`
   / `stage`（`http`|`timeout`|`connect`）/ `netCode` / `failReason` / `hint`。
   上层汇总直接用这些字段，**不要读 `err.message`** —— Node 的 fetch 只会给一句 `fetch failed`，
   真正的原因在 `err.cause` 里，已被 `logger.describeError()` 翻译过。
