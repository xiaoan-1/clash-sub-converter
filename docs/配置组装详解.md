# 配置组装过程

本文档详细说明 `src/converter.js` 如何将解析结果组装成完整的 Clash YAML 配置。

---

## 组装入口

**文件**：`src/converter.js`  
**函数**：`convertToClash(proxies, options)`

```js
convertToClash(proxies, options)
```

### 输入

| 参数 | 来源 | 说明 |
|------|------|------|
| `proxies` | `src/parser.js` → `parseSubscription()` | 统一代理对象数组 |
| `options.ruleOptions` | `index.js` → `parseRuleOptions()` | OpenClash 的 include/exclude 解析结果 |

### 输出

完整的 Clash YAML 字符串，直接返回给 OpenClash。

---

## 组装的 5 个部分

```
convertToClash()
    │
    ├─ ① 基础配置        硬编码默认值
    ├─ ② DNS 配置        源订阅自带则透传，否则不注入
    ├─ ③ proxies         直接使用 parser.js 的输出
    ├─ ④ proxy-groups    generateProxyGroups(proxies)  ← src/proxy-groups.js
    └─ ⑤ rules           generateRules(ruleOptions)    ← src/rule-manager.js
```

---

## ① 基础配置

**来源**：硬编码默认值

```js
const config = {
  'mixed-port': 7890,        // HTTP/SOCKS5 混合端口
  'allow-lan': true,         // 允许局域网连接
  'bind-address': '*',       // 监听所有网卡
  mode: 'rule',              // 规则模式
  'log-level': 'info',       // 日志级别
  'external-controller': '127.0.0.1:46011'  // 外部控制器地址
};
```

如果有 `secret` 参数，还会加上 `config.secret`。

---

## ② DNS 配置

**来源**：源订阅自带的 `dns` 段（若有）；否则**不注入**任何 DNS 配置

```js
// index.js / server/api.js：转换前先提取源订阅自带的 DNS，有则原样透传
const srcDns = extractClashDns(content);   // 见 src/parser.js
const convertOptions = { ... };
if (srcDns) convertOptions.dns = srcDns;

// converter.js：dns 默认值为 null，源无 DNS 时输出不带 dns 段
dns = null,
...
if (dns) config.dns = dns;   // 仅在调用方传入时注入
```

> **设计原则**：转换结果与「直接用订阅链接导入」严格等价 —— 源配置带 DNS 就透传，
> 不带就不注入，把 DNS 决定权交还客户端（Clash Verge / 内核默认行为）。
> 曾因默认注入含被墙 fallback 的 DNS，导致节点服务器域名解析失败、全部超时，
> 因此不再维护「默认 DNS」：源订阅若无 DNS，输出也保持无 DNS。

---

## ③ proxies（代理节点）

**来源**：直接使用 `parser.js` 的输出，不做任何处理

```js
config.proxies = proxies;
```

每个节点的结构参考 `docs/代理协议解析.md`。

---

## ④ proxy-groups（代理分组）

**来源**：`src/proxy-groups.js` → `generateProxyGroups(proxies)`

### 输入

- `proxies[]`：解析后的节点数组

### 处理流程

```
proxies[]
    │
    ├─ 遍历每个节点
    │   └─ getRegion(proxy.name)
    │       ├─ 先检查是否匹配 CN_KEYWORDS → '🇨🇳 中国大陆'
    │       └─ 再检查 REGION_KEYWORDS (22 个地区)
    │
    ├─ 按地区分组
    │   ├─ domesticProxies[]     国内节点
    │   └─ regionMap{}           地区 → 节点名数组
    │       ├─ '🇭🇰 香港': ['香港节点01', 'HK-02', ...]
    │       ├─ '🇯🇵 日本': ['东京节点', 'JP-01', ...]
    │       ├─ '🇺🇸 美国': ['US-01', '洛杉矶', ...]
    │       └─ ...
    │
    └─ 生成分组配置
```

### 输出的分组（当前版本）

| 序号 | 分组名 | 类型 | 包含的节点 | 说明 |
|------|--------|------|-----------|------|
| 1 | 🚀 节点选择 | select | ♻️ 自动选择, DIRECT, 所有节点 | 主分组（必须） |
| 2 | ♻️ 自动选择 | url-test | 非国内节点 | 自动选最低延迟（必须） |
| 3 | 🇨🇳 中国大陆 | select | DIRECT + 国内节点 | 国内流量直连（可选） |
| 4~17 | 14 个规则分组 | select | defProxy 排头 + 其余固定选项 + 所有节点 | 服务分组（可选） |
| 18 | 🐟 漏网之鱼 | select | 🚀 节点选择 + DIRECT + 所有节点 | 兜底（必须） |

### 关键逻辑

**规则分组 proxies 排序**（Clash 以 proxies[0] 为默认出口）：
```js
const fixedOptions = ['🚀 节点选择', '♻️ 自动选择', 'DIRECT'];
const defProxy = ruleCfg?.defaultProxy || '♻️ 自动选择';
const otherOptions = fixedOptions.filter(o => o !== defProxy);
// defProxy 排第一位（Clash 默认出口）
groups.push({
  name: ruleCfg?.name || rc.name,
  type: 'select',
  proxies: [defProxy, ...otherOptions, ...activeProxies],
  defaultProxy: defProxy
});
```

**固定选项下拉**：前端 UI 中每个规则分组的下拉框有三个固定选项：
```js
var proxyOptions = ['🚀 节点选择', '♻️ 自动选择', 'DIRECT'].concat(activeNames);
```

## ⑤ rules（路由规则）

**来源**：`src/rule-manager.js` → `generateRules(ruleOptions)`

### 输入

`ruleOptions` 对象，由 `index.js` 的 `parseRuleOptions()` 生成：

```js
{
  includeTelegram: true,    // OpenClash include=(?i)telegram 匹配到
  includeOpenai: true,      // OpenClash include=(?i)openai 匹配到
  includeYoutube: false,    // 未匹配
  includeNetflix: false,
  includeDisney: false,
  includeDazn: false,
  includeBahamut: false,
  includeBilibili: false,
  includeGitHub: false,
  includeMiHoYo: false
}
```

### 处理流程

```
ruleOptions
    │
    ├─ includeTelegram: true  → getTelegramRules()   → 38 条规则
    ├─ includeOpenai: true    → getOpenAIRules()     → 11 条规则
    ├─ includeYoutube: false  → 跳过
    ├─ includeNetflix: false  → 跳过
    └─ ...
        │
        ├─ 始终包含：GEOIP,CN,🇨🇳 中国大陆
        ├─ 始终包含：LAN 直连规则
        └─ 始终包含：MATCH,🐟 漏网之鱼（兜底）
```

### 输出的规则结构（15 组）

```
rules = [
  // Apple 直连规则
  'DOMAIN-SUFFIX,apple.com,🍎 Apple 服务',
  // Microsoft 直连规则
  'DOMAIN-KEYWORD,microsoft,Ⓜ️ 微软服务',

  // GeoIP 国内直连
  'GEOIP,CN,DIRECT',

  // Telegram 规则（38 条，includeTelegram=true 时）
  'DOMAIN-SUFFIX,telegram.org,💬 Telegram',

  // OpenAI 规则（11 条，includeOpenai=true 时）
  'DOMAIN-SUFFIX,openai.com,🤖 OpenAI',

  // Claude 规则（includeClaude=true 时）
  'DOMAIN-SUFFIX,claude.ai,🤖 Claude',

  // Gemini 规则（includeGemini=true 时）
  'DOMAIN-SUFFIX,gemini.google.com,🤖 Gemini',

  // ... 共 15 组规则

  // 兜底
  'MATCH,🐟 漏网之鱼'
]
```

## 最终组装

```js
const config = {
  // ① 基础配置
  'mixed-port': 7890,
  'allow-lan': true,
  'bind-address': '*',
  mode: 'rule',
  'log-level': 'info',
  'external-controller': '127.0.0.1:46011',

  // ② DNS 配置
  dns: { ... },

  // ③ 代理节点
  proxies: [ ... ],           // ← parser.js 直接传入

  // ④ 代理分组
  'proxy-groups': [ ... ],    // ← proxy-groups.js 生成

  // ⑤ 路由规则
  rules: [ ... ]              // ← rule-manager.js 生成
};

// 序列化为 YAML
return yaml.dump(config, {
  lineWidth: -1,      // 不自动换行
  noRefs: true,       // 不使用 YAML 引用
  sortKeys: false,    // 保持插入顺序
  quotingType: "'",   // 单引号
  forceQuotes: false  // 仅必要时加引号
});
```

## 数据来源汇总

| 配置部分 | 数据来源 | 是否依赖外部输入 |
|----------|----------|----------------|
| 基础配置 | 硬编码默认值（可传参覆盖） | ❌ |
| DNS 配置 | 源订阅自带 `dns` 段时透传（默认不注入） | ✅ 依赖订阅源 |
| proxies | `parser.js` → `parseSubscription()` | ✅ 依赖订阅源 |
| proxy-groups | `proxy-groups.js` → `generateProxyGroups(proxies)` | ✅ 依赖节点数据 |
| rules | `rule-manager.js` → `generateRules(ruleOptions)` | ✅ 依赖 OpenClash 的 include/exclude |

> 用户配置基准为 `config/default.json`（由部署人员直接编辑）；访客差异存于 `guests/<IP>.json`。
