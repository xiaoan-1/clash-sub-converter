# Clash 订阅转换器 — 主流程详解

> 以 10 个代理节点为例，完整走一遍从订阅 URL 到 Clash YAML 配置的全流程。

---

## 总览

```
用户请求 /sub?url=https://xxx
        │
        ▼
┌─────────────────────────────────────────────────────┐
│  1. 获取订阅内容  fetchSubscription(url)              │
│     → 返回原始文本（Base64 / URI 列表 / Clash YAML）  │
└─────────────────┬───────────────────────────────────┘
                  ▼
┌─────────────────────────────────────────────────────┐
│  2. 解析节点  parseSubscription(content)              │
│     → 返回 10 个代理对象                              │
└─────────────────┬───────────────────────────────────┘
                  ▼
┌─────────────────────────────────────────────────────┐
│  3. 生成分组  generateProxyGroups(proxies, options)   │
│     → 读取用户配置（config.json）                     │
│     → 读取规则定义（config/rules/*.json）             │
│     → 按地区分类节点                                  │
│     → 组装分组数组                                    │
└─────────────────┬───────────────────────────────────┘
                  ▼
┌─────────────────────────────────────────────────────┐
│  4. 生成规则  ruleManager.generateRules(options)      │
│     → 读取规则定义中的 DOMAIN / IP-CIDR 等            │
│     → 匹配规则 → 分流到对应分组                       │
└─────────────────┬───────────────────────────────────┘
                  ▼
┌─────────────────────────────────────────────────────┐
│  5. 组装配置  convertToClash(proxies, options)        │
│     → DNS（源订阅自带则透传，否则不注入）             │
│     → proxies（原始节点）                             │
│     → proxy-groups（步骤 3 的分组）                   │
│     → rules（步骤 4 的规则）                          │
│     → YAML 序列化输出                                │
└─────────────────────────────────────────────────────┘
```

---

## 第 1 步：获取订阅内容

**入口**: `GET /sub?url=https://xxx`

```js
// index.js
const content = await fetchSubscription(url);
```

- 支持多个 URL（用 `|` 分隔）
- `fetchSubscription()` 发送 HTTP GET，拿到原始文本
- 内容可能是：Base64 编码的 URI 列表、纯 URI 列表、或 Clash YAML 配置

## 第 2 步：解析节点（parser.js）

```js
const proxies = parseSubscription(content);
```

`parseSubscription` 内部会尝试三种格式：

### 2a. Clash YAML 格式
```yaml
proxies:
  - name: "🇭🇰 香港 01"
    type: vmess
    server: 1.2.3.4
    port: 443
    uuid: xxxx-xxxx
```
→ `tryParseClashYaml()` 用 `js-yaml` 解析，提取 `proxies` 数组

### 2b. URI Scheme 格式
```
vmess://base64({json})
ss://base64(method:password)@server:port#name
trojan://password@server:port?...#name
vless://uuid@server:port?...#name
hysteria2://password@server:port?...#name
hysteria://auth@server:port?...#name
anytls://password@server:port?...#name
tuic://uuid:password@server:port?...#name
snell://psk@server:port?...#name
socks5://user:pass@server:port#name
http://user:pass@server:port#name
wireguard://privateKey@server:port?...#name
shadowquic://user:pass@server:port?...#name
ssr://base64(...)
```

→ 逐行识别前缀，调用对应的 `parseVmess` / `parseShadowsocks` / ...

### 2c. Base64 包装
有些订阅返回的是整个内容 Base64 编码的，先解码再走上面的流程

## 第 3 步：地区识别（proxy-groups.js → getRegion）

每个节点的 `name` 会经过 `getRegion()` 进行地区识别：

```js
function getRegion(name) {
  const upper = name.toUpperCase();
  // 1️⃣ 先匹配具体地区：命中即视为国际节点
  for (const [region, matcher] of REGION_MATCHERS) {
    if (matcher(upper)) return region;
  }
  // 2️⃣ 再看是否国内
  if (DOMESTIC_MATCH(upper)) return '🇨🇳 中国大陆';
  // 3️⃣ 无法识别
  return null;
}
```

> 顺序很关键：`[台湾省] 中华电信` 同时含「台湾」（地区）与「电信」（国内关键词），
> 先匹配地区才能避免把台湾节点误判成国内节点。
>
> 短 ASCII 关键词（CN / IN / HK …）按**词边界**匹配：`CN2 GIA`、`KINX` 不会被误判为国内。

**关键词来源**: `config/regions.json`

```
国内关键词: 国内, 中国, China, CN, 广州, 上海, 北京, 深圳, 杭州, 成都, 武汉, 移动, 联通, 电信, 广电
地区关键词: 🇭🇰 香港 → [香港, HK, Hong Kong, 🇭🇰]
            🇯🇵 日本 → [日本, JP, Japan, 🇯🇵]
            ...共 22 个地区
```

## 第 4 步：分组组装（proxy-groups.js → generateProxyGroups）

### 4a. 读取用户配置

```js
// converter.js
const userConfig = readConfig();  // 读取根目录 config.json（user-config.js）
const userGroups = userConfig?.groups || [];
```

用户配置格式（根目录 `config.json`）：

```json
{
  "groups": [
    { "builtin": "select",    "name": "🚀 节点选择" },
    { "builtin": "auto",      "enabled": true },
    { "builtin": "domestic",  "enabled": true },
    { "builtin": "regions",   "enabled": true },
    { "ruleId": "telegram",   "enabled": true,  "defaultProxy": "♻️ 自动选择" },
    { "ruleId": "openai",     "enabled": false },      { "ruleId": "claude",     "enabled": true,  "defaultProxy": "♻️ 自动选择" },    { "ruleId": "youtube",    "enabled": true,  "defaultProxy": "🇺🇸 美国 01" },
    { "builtin": "fallback",  "name": "🐟 漏网之鱼" }
  ]
}
```

### 4b. 构建查找表

```js
const builtinMap = new Map();  // builtin → config
const ruleMap = new Map();     // ruleId → config
let regionsEnabled = true;

// 遍历 userGroups 建立索引
for (const ug of userGroups) {
  if (ug.builtin === 'regions') regionsEnabled = ug.enabled !== false;
  else if (ug.builtin)          builtinMap.set(ug.builtin, ug);
  else if (ug.ruleId)           ruleMap.set(ug.ruleId, ug);
}
```

### 4c. 逐个生成分组

#### ① 🚀 节点选择（必须，始终生成）

```js
{
  name: '🚀 节点选择',
  type: 'select',
  proxies: ['♻️ 自动选择', '🇨🇳 中国大陆', '🇭🇰 香港 01', '🇭🇰 香港 02', '🇯🇵 日本 01', '🇯🇵 日本 02', '🇸🇬 新加坡 01', '🇺🇸 美国 01', '🇺🇸 美国 02', '🇬🇧 英国 01', '国内专线 01', '国内专线 02']
}
```
- 放在最前面
- 包含所有节点 + 自动选择 + 中国大陆
- **Clash 默认使用这个分组作为入口**

#### ② ♻️ 自动选择（可选，默认开）

```js
// 检查: builtinMap.get('auto') → { enabled: true } → 不跳过
{
  name: '♻️ 自动选择',
  type: 'url-test',
  url: 'http://www.gstatic.com/generate_204',
  interval: 300,
  proxies: ['🇭🇰 香港 01', '🇭🇰 香港 02', '🇯🇵 日本 01', '🇯🇵 日本 02', '🇸🇬 新加坡 01', '🇺🇸 美国 01', '🇺🇸 美国 02', '🇬🇧 英国 01']  // 仅国际节点
}
```
- 自动测速，选择延迟最低的节点
- **不含国内节点**（避免自动选到国内节点访问国际服务）

#### ③ 🇨🇳 中国大陆（可选，默认开）

```js
// 检查: builtinMap.get('domestic') → { enabled: true } → 不跳过
{
  name: '🇨🇳 中国大陆',
  type: 'select',
  proxies: ['DIRECT', '国内专线 01', '国内专线 02']
}
```
- 含 `DIRECT`（直连），用于访问国内服务
- 仅包含国内节点

#### ④ 地区分组（可选，默认开）

```js
// 检查: regionsEnabled → true → 不跳过
// 每个非空地区生成一个 url-test 分组
```

生成 5 个地区分组：

```js
{ name: '🇭🇰 香港',   type: 'url-test', proxies: ['🇭🇰 香港 01', '🇭🇰 香港 02'] }
{ name: '🇯🇵 日本',   type: 'url-test', proxies: ['🇯🇵 日本 01', '🇯🇵 日本 02'] }
{ name: '🇸🇬 新加坡', type: 'url-test', proxies: ['🇸🇬 新加坡 01'] }
{ name: '🇺🇸 美国',   type: 'url-test', proxies: ['🇺🇸 美国 01', '🇺🇸 美国 02'] }
{ name: '🇬🇧 英国',   type: 'url-test', proxies: ['🇬🇧 英国 01'] }
```

#### ⑤ 规则分组（可选，默认开）

读取 `config/rules/*.json`（共 15 个文件），跳过 `common.json`（纯规则不生成分组），为其余 14 个规则生成分组：

```
telegram.json → 💬 Telegram    openai.json   → 🤖 OpenAI
youtube.json  → 📺 YouTube      netflix.json  → 🎬 Netflix
claude.json   → 🤖 Claude       gemini.json   → 🤖 Gemini
...（共 14 个）
（common.json 跳过，它是纯规则不生成分组）
```

**关键排序逻辑**：每个规则分组的代理列表由 `defaultProxy` 决定排序，Clash 将 `proxies[0]` 作为默认出口：

```js
const fixedOptions = ['🚀 节点选择', '♻️ 自动选择', 'DIRECT'];
const defProxy = ruleCfg?.defaultProxy || '♻️ 自动选择';
// defProxy 排第一位，其余两个固定选项随其后，最后追加所有活跃节点
proxies: [defProxy, ...otherOptions, ...activeProxies]
```

对照用户配置：
- `telegram` → `enabled: true` → ✅ 生成
- `openai` → `enabled: false` → ❌ 跳过
- `youtube` → `enabled: true`, `defaultProxy: '🇺🇸 美国 01'` → ✅ 生成，defProxy=🇺🇸 美国 01 排第一位

```js
{
  name: '💬 Telegram',
  type: 'select',
  proxies: ['♻️ 自动选择', '🚀 节点选择', 'DIRECT', '🇭🇰 香港 01', '🇭🇰 香港 02', '🇯🇵 日本 01', ...],
  defaultProxy: '♻️ 自动选择'
}
// youtube 的 defProxy='🇺🇸 美国 01' 排在第一位
// claude, gemini, netflix 等类推...
```

#### ⑥ 🐟 漏网之鱼（必须，始终生成）

```js
{
  name: '🐟 漏网之鱼',
  type: 'select',
  proxies: ['🚀 节点选择', '🇨🇳 中国大陆', 'DIRECT', '🇭🇰 香港 01', '🇭🇰 香港 02', '🇯🇵 日本 01', '🇯🇵 日本 02', '🇸🇬 新加坡 01', '🇺🇸 美国 01', '🇺🇸 美国 02', '🇬🇧 英国 01', '国内专线 01', '国内专线 02']
}
```
- 兜底分组，未被任何规则匹配的流量走这里

## 第 5 步：规则生成（rule-manager.js → generateRules）

```js
const rules = ruleManager.generateRules(ruleOptions);
```

遍历每个规则配置的 `rules` 数组（共 15 个文件，common 始终启用，其余按 include/exclude 过滤）：

```
telegram.json 的 rules: [
  "DOMAIN-SUFFIX,t.me",
  "DOMAIN-SUFFIX,telegram.org",
  "IP-CIDR,91.108.4.0/22",
  ...
]
```

输出 Clash 格式规则（规则的 target 自动设为规则名）：

```yaml
rules:
  - DOMAIN-SUFFIX,cdn-telegram.org,💬 Telegram
  - DOMAIN-SUFFIX,t.me,💬 Telegram
  - DOMAIN-SUFFIX,openai.com,🤖 OpenAI
  - DOMAIN-SUFFIX,claude.ai,🤖 Claude
  - DOMAIN-SUFFIX,gemini.google.com,🤖 Gemini
  - DOMAIN-SUFFIX,youtube.com,📺 YouTube
  - GEOIP,CN,🇨🇳 中国大陆        # common 规则
  - MATCH,🐟 漏网之鱼             # 兜底
```

> **流量匹配规则 → 进入对应的分组 → 分组从自己的 proxies 中选出一个节点 → 流量走该节点出去**

## 用户配置的控制点

| 控制点 | 位置 | 作用 |
|--------|------|------|
| `groups[].enabled` | `config.json` | 开关某个分组，设 `false` 则不生成 |
| `groups[].defaultProxy` | `config.json` | 设定分组默认使用哪个节点 |
| `groups[].name` | `config.json` | 覆盖分组显示名称 |
| 规则文件 `config/rules/*.json` | 磁盘 | 定义每个分组的匹配规则和代理策略 |
| `config/regions.json` | 磁盘 | 定义地区识别关键词和覆盖范围 |
